# Git and docs
- One small commit per completed task, message format `type: summary`.
- Branch per phase: `phase-1-setup`, `phase-2-core`, etc., merged to `main` when done.
- After any API change update `docs/API.md`.
- After any architecture change update `docs/ARCHITECTURE.md`.
- Keep a running list of decisions in `docs/INTERVIEW_NOTES.md` (what, why, trade-off).
